Fase 2. Introduccion y requisitos previos

Que es NESS Relay

NESS Relay es un agente que se instala en Linux para conectarse por SNMP a tus equipos de red (firewalls, routers, switches y servidores) y enviar la telemetria a NESS HQ.

Que necesitas antes de empezar

  • Un servidor Linux con acceso a internet.
  • Acceso de administrador (root o sudo).
  • Token API de NESS HQ (te lo entrega el equipo NESS).
  • IP de tus dispositivos y credenciales SNMP.
  • El archivo instalador y el binario del agente en la misma carpeta.
Importante: sin token API y sin SNMP activo en tus dispositivos, el agente se instala pero no podra enviar datos utiles.

Mini glosario (sin tecnicismos)

SNMP: idioma estandar para preguntar estado a equipos de red.
Token API: llave secreta para que NESS reconozca tu agente.
Cron: programador automatico para ejecutar tareas cada cierto tiempo.
Smart Tester: asistente que revisa si todo esta listo antes de operar.

Fase 3. Instalacion del agente (cliente final)

El proceso oficial para cliente final es usar el instalador interactivo. Este instalador crea carpetas, variables de entorno, scripts y programacion automatica.

Paso 1. Entrar a la carpeta del instalador

Ubicate donde estan los archivos install_relay.sh y el binario ness-relay (o ness-relay-x86_64 / ness-relay-aarch64).

cd /ruta/del/agente && ls
Paso 2. Ejecutar instalacion
sudo ./install_relay.sh

El asistente te pedira aceptar terminos, ejecutar Smart Tester y luego completar servidor + token + dispositivos.

Paso 3. Seleccionar servidor NESS
  • 1 = On-premise
  • 2 = Testing
  • 3 = Public Cloud

Si no sabes cual usar, el valor tipico es 3 (Public Cloud).

Paso 4. Ingresar NESS_API_TOKEN

Debes pegar exactamente el token entregado por NESS. Si tiene error, veras fallos tipo autenticacion HTTP 401.

Paso 5. Configurar dispositivos

Seleccionas fabricante, IP, puerto SNMP y credenciales SNMP. Puedes agregar varios dispositivos por cada vendor.

Que crea el instalador

RutaUso

/opt/ness_relay/logsLogs de instalacion y operacion

Resultado esperado: al final debes ver mensaje de instalacion completada y una tarea cron cada 5 minutos.

Fase 4. Configuracion SNMP (explicado facil)

Resumen rapido

Version Seguridad Recomendacion
SNMPv1BajaSolo si no hay alternativa
SNMPv2cMedia-bajaComun en equipos antiguos
SNMPv3AltaRecomendado para produccion

SNMPv3 en palabras simples

  • Usuario: nombre del usuario SNMPv3.
  • Auth protocol: forma de validar identidad (ejemplo: SHA, SHA256).
  • Auth password: clave de autenticacion.
  • Priv protocol: cifrado de datos (ejemplo: AES128, AES256).
  • Priv password: clave de cifrado.
Tip rapido: si no tienes politica especial, empieza con SHA + AES128 para evitar incompatibilidades.

Ejemplo del archivo connection.config

fortinet_count=1 fortinet_1_ip=192.168.10.99 fortinet_1_port=161 fortinet_1_vendor=fortinet fortinet_1_description=Firewall principal fortinet_1_snmp_version=3 fortinet_1_v3_user=relay-user fortinet_1_v3_auth_protocol=SHA256 fortinet_1_v3_auth_password=TU_PASSWORD_AUTH fortinet_1_v3_priv_protocol=AES256 fortinet_1_v3_priv_password=TU_PASSWORD_PRIV
Seguridad: este archivo contiene credenciales, por eso queda protegido con permisos 600 y acceso root.

Fase 5. Smart Tester explicado de inicio a fin

Smart Tester es un diagnostico previo para detectar problemas antes de poner el agente en produccion. Te ahorra tiempo y evita instalaciones fallidas.

Fase A. System Readiness

  • Verifica si cron esta instalado y activo.
  • Puede intentar corregir automaticamente si falta cron.
  • Confirma estado de servicio cron/crond.

Fase B. Network Health

  • Prueba ping a gateway local.
  • Prueba ping a dispositivos.
  • Valida salida HTTPS hacia NESS (cloud/on-premise).

Fase C. Deep SNMP Validation

  • Intenta lectura SNMP real de sysName.
  • Clasifica errores SNMP (timeout, auth, engineID, etc.).
  • Da sugerencias especificas por vendor.

Fase D. Local Firewall Checker

  • Revisa reglas locales en ufw, firewalld, iptables, nftables.
  • Advierte si UDP 161 parece bloqueado.

Autocompletado inteligente

Si validas manualmente un dispositivo y pasa SNMP, Smart Tester guarda temporalmente esos datos y el instalador puede reutilizarlos para que no vuelvas a escribir todo.

Resultado ideal: gateway OK + salida HTTPS OK + SNMP OK. Con eso el agente queda listo para operar.

Fase 7. Operacion y monitoreo diario

Ejecucion manual

sudo /opt/ness_relay/executables/run_relay.sh

Programacion automatica

El instalador registra cron cada 5 minutos.

crontab -l | grep ness_relay

Como ver logs

tail -f /opt/ness_relay/logs/ness_relay.log

Ciclo de recoleccion (resumen)

  1. Cargar perfil de vendor.
  2. Probar conectividad SNMP.
  3. Recolectar sistema.
  4. Recolectar rendimiento.
  5. Recolectar interfaces.
  6. Recolectar seguridad.
  7. Recolectar datos especificos del vendor.
  8. Analizar, exportar y enviar al servidor.

Fase 8. Actualizacion y mantenimiento

  • El agente tiene modulo de actualizacion para consultar version remota.
  • El instalador detecta instalaciones existentes y permite elegir:
    • Reinstalar completo
    • Actualizar configuracion
    • Cancelar
  • En reinstalaciones crea backup en /opt/ness_relay_backup_FECHA_HORA.
Buena practica: antes de cambios grandes, respalda connection.config y valida con Smart Tester.

Fase 9. Solucion de problemas (FAQ)

1) Error de token o HTTP 401

El token es incorrecto o no coincide con el servidor elegido.

Solucion: validar NESS_API_TOKEN y volver a probar.

2) Timeout SNMP

El puerto UDP 161 esta bloqueado, el dispositivo no responde o credenciales incorrectas.

Solucion: revisar firewall, reachability y credenciales SNMP.

3) Smart Tester muestra salida HTTPS fallida

Hay problema de DNS, proxy o salida a internet.

Solucion: validar ruta de red y resolucion de nombres.

4) Cron no ejecuta

Servicio cron deshabilitado o entrada no instalada.

Solucion: verificar estado del servicio y crontab.

5) No aparecen datos en NESS HQ

Puede ser token, servidor equivocado o todos los dispositivos fallando SNMP.

Solucion: ejecutar run_relay.sh manualmente y revisar logs.

Fase 10. Cierre y checklist final

Antes de entregar la instalacion como completada, confirma este checklist:

  • Instalador ejecutado sin errores criticos.
  • connection.config creado en /opt/ness_relay/configs.
  • Smart Tester con validaciones clave en verde.
  • Ejecucion manual correcta con run_relay.sh.
  • Cron configurado cada 5 minutos.
  • Log generandose en /opt/ness_relay/logs/ness_relay.log.
Si todo lo anterior esta OK: el agente ya esta listo para produccion.
